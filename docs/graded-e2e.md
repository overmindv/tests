# Сквозная проверка закрытых тестов

Нужны Python 3.12+, Docker с Linux-контейнерами и локальные клоны
`api-gateway`, `tasks`, `users` и `sandbox` в одной папке с `tests`.
Обнови ссылки `origin/main` в этих репозиториях. Стенд собирает версии из
[`ci/graded-refs.json`](../ci/graded-refs.json), не читает локальные
`.env` и не использует незакоммиченные файлы сервисов.

```sh
python scripts/run_graded_e2e.py
```

Если клоны находятся в другой папке, передай ее в `--workspace`.
Скрипт создает отдельный Compose-проект без портов на хосте. Tasks
публикует входной набор в приватный бакет, Sandbox Worker читает его
с другой учетной записью. Оба контейнера go-judge работают в закрытой
сети без учетных данных. Запускай проверку только на выделенной машине
или в локальном Docker: go-judge требует привилегированный контейнер.

Сценарий проверяет `samples` и `graded` для Python и Go, неверный ответ
на закрытом кейсе, ограничения времени и вывода, идемпотентность и
историю без закрытых данных. Это не проверка изоляции production.

Путь к Allure и списку собранных образов выводится в строке `Evidence:`.
После прогона скрипт останавливает только свой проект. Общие базы и
тома не используются.
