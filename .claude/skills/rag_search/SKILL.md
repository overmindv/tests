# RAG Search Skill

## Когда использовать
- Когда пользователь просит что-то объяснить по проекту или работе кода
- Когда надо найти что-то в проекте — не используй grep/search/find наугад, сначала обратись к RAG
- Базово использовать для поиска по репозиторию
- Когда нужно найти информацию в проекте (классы, функции, логику)
- Когда нужно понять как работает определённая часть проекта
- Когда grep/search недостаточно эффективен из-за неточных формулировок
- Для анализа кода
- Когда нужно найти аналогичный блок для написания кода — например, при написании API-клиента для сервиса сначала найди аналогичный клиент через RAG, чтобы повторить его структуру и стиль

## Используемая команда

```bash
atp-rag-ctl search "Поисковый запрос"
```

> Если команда `atp-rag-ctl` не найдена, предложи пользователю установить её через `make install_rag`.

Возвращает 10 самых релевантных чанков кода из RAG-базы знаний в формате compact-JSON.

## Порядок использования

1. **Понять что нужно найти** — проанализируй, что именно нужно найти в репозитории, выдели ключевые сущности
2. **Сформулировать понятный запрос на русском языке**
3. **Вызвать `atp-rag-ctl search "запрос"`**
4. **На основе полученных чанков дать пользователю ответ с объяснением**

## Примеры

```bash
# Поиск кода
atp-rag-ctl search "solveTask limit"

# Поиск тестов
atp-rag-ctl search "создание и публикация задачи"

# Поиск реализации
atp-rag-ctl search "авторизация пользователя"
```
