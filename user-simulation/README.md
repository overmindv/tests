# Симуляция пользователей в браузере

Воспроизводимые сценарии с фиксированными целями и типичными ошибками для
студента и автора/модератора. Это автоматизированная проверка поведения UI,
а не интервью, замер удовлетворённости или статистика реальных пользователей.
Существующий `make test` (pytest/GraphQL/Allure) не меняется.

## Установка и запуск

Нужны Node.js 22.15+ и npm. Версия Playwright зафиксирована в package.json и lock.
Из репозитория `tests`:

```bash
make simulation-setup
make simulation-list
make simulation-check
make simulation-privacy
# Нужны уже установленные зависимости frontend; стек не требуется.
make simulation-local
make simulation-report
```

`simulation-local` запускает временный Vite из соседнего `frontend` на порту
5174 и останавливает его после тестов. Занятый порт вызывает ошибку. Для уже
запущенного frontend: `SIM_BASE_URL=http://localhost:3000 make simulation-smoke`.
Если основной npm registry недоступен, допустимо установить только здесь:
`cd user-simulation && npm ci --registry=https://registry.npmjs.org`.
На Linux для Chromium могут понадобиться `npx playwright install --with-deps chromium`.

Два проекта: Chromium 1366×900 (ноутбук), Chromium с профилем Pixel 7 393×727
(телефон, touch). Это эмуляция viewport/device, не физический Android или Safari.
Один worker, без retry: сбой не прячется за повторными попытками.

## Два уровня доказательств

**`@smoke`: UI при недоступном API.** Реальные frontend, маршрутизатор, формы и
CSS; `page.route('**/graphql', route.abort(...))` — явная fault fixture.
Она гарантирует отсутствие сессии и воспроизводимые сетевые ошибки. Успех smoke
не подтверждает работу входа, каталога, сервисов, публикации или решения задач.
Он проверяет навигацию, guest guard, восстановление после неверного email и
сброс локальных фильтров. Никаких ответов с вымышленными задачами/вердиктами нет.

**`@live`: настоящий браузерный journey через frontend → gateway → сервисы.**
Перехватов API и подставленных сессий нет; вход — через форму и httpOnly cookie.
Нужен поднятый выделенный стек и два различных заранее подготовленных аккаунта:
автор с admin-правами и обычный студент. На данный момент продукт предоставляет
авторские/модераторские действия через admin; отдельные роли не выдумываются.
Данные и роли готовят существующими fixtures/фасадом `tests/src/api/gateway.py`
либо штатным администрированием; второй HTTP/API-клиент в этом runner не создаётся.

Экспортируйте `SIM_BASE_URL`, `SIM_DEDICATED_STACK=1`, `SIM_ADMIN_EMAIL`,
`SIM_ADMIN_PASSWORD`, `SIM_STUDENT_EMAIL`, `SIM_STUDENT_PASSWORD` из локального
секретного окружения (см. `.env.example`), затем:

```bash
make simulation-live
# По одному устройству:
cd user-simulation
npm run test:live -- --project=phone-chromium
```

`.env` автоматически не читается. Не передавайте пароли строкой команды и не
публикуйте их. Отсутствие обязательных переменных завершает live-тест ошибкой,
а не зелёным skip. Одни и те же student/admin аккаунты нельзя использовать
параллельно в другом прогоне: проверяются две последние попытки пользователя.

Live-сценарий: автор вводит одинаковые варианты → видит ошибку → исправляет →
создаёт черновик → публикует; студент не получает редактор → выбирает неверный
ответ → исправляет → видит accepted → после reload открывает обе попытки и
проверяет их связь с созданной задачей. Автор удаляет только созданную задачу
в `finally`. Неверные результаты тест не принимает как успех.

Удаление задачи мягкое; попытки студента остаются в его истории. Аккаунты runner
не удаляет. Нужен отдельный сбрасываемый тестовый стек; автоматического `make clean`
нет. При падении очистки задача может остаться — это отдельный failed step отчёта.
В admin-списке ожидается видимость нового объекта на первой странице; при активном
наполнении/другой сортировке тест может потребовать изолированных данных.

## Покрытие и границы

| Цель | Гостевой smoke | Live, требует стека | Ещё не автоматизировано |
|---|---|---|---|
| Студент: найти практику | Меню → задачи, сброс фильтров | Открытие созданной задачи по URL | Поиск по всему каталогу, prerequisites |
| Студент: авторизация | Guard истории, невалидный email, ошибка API | Реальный вход и восстановление cookie после reload | Регистрация, забытый пароль |
| Студент: решить и проверить прогресс | Нет | Неверный → верный ответ, обе сохранённые попытки | Programming/sandbox, multiple choice |
| Автор: подготовить материал | Guard admin | Дубликат варианта → исправление → черновик | Новая неизменяемая версия |
| Автор: опубликовать | Нет | Публикация и удаление своей тестовой задачи | Архивирование, topic binding |
| Модератор: сбор/проверка | Guest guard `/admin/collected-tasks` | Нет | Импорт, источник, редактор кандидата, модерация |
| Телефон/ноутбук | Все 5 сценариев × 2 | Один полный сценарий × 2 | Safari/WebKit, реальное устройство, screen reader |

Границы coverage намеренно видимы: наличие guard модератора не означает
покрытие самой модерации. Одинаковый приоритет ролей не означает одинаковый
объём уже реализованного покрытия.

## Артефакты и интерпретация

`artifacts/` исключён из git. Smoke сохраняет HTML-отчёт, `results.json` и PNG
ключевых экранов/ошибок. Каждый PNG прикреплён к шагу/тесту и имеет проект в пути.
Live использует отдельный `live-results.json` с outcome, ошибками и путями PNG;
API steps намеренно не сериализуются, поскольку `fill` может раскрыть пароль.
Пароли/email редактируются в сообщениях live-репортера и в `testInfo.errors`
до встроенной записи `error-context.md` (включая matcher `errorContext`). В config
установлен встроенный для закреплённой версии `PLAYWRIGHT_NO_COPY_PROMPT=1`:
он предотвращает сбор DOM/ARIA snapshot с заполненными credentials. Это не
публичная опция типизированного config; при обновлении Playwright обязателен
`make simulation-privacy`. Проверка запускает два вида намеренного падения на
двух устройствах, включая matcher error с введённым паролем, и сканирует **все**
файлы отдельного `artifacts/privacy/` вместе с stdout/stderr. Пароль/email
генерируются заново, проверяются raw/JSON/URL формы, trace/HAR/video запрещены.
Артефакты после проверки не удаляются: утечка завершает проверку ошибкой.
Trace,
video, HAR, storageState, request/response dumps и console collector выключены.
Скриншоты маскируют password/email/phone inputs. Используйте только синтетические
данные: остальной видимый контент screenshots маскированием не покрывается.
Не запускайте live напрямую через `npx playwright test` без `SIM_LIVE=1`:
используйте npm/Make target с безопасным live-репортером.

В отчёте наблюдений отделяйте: проверенный факт (шаг/PNG), гипотезу влияния,
предлагаемый следующий эксперимент и непроверенное. Не вычисляйте проценты
удовлетворённости/конверсии из результата этих тестов. Дата, команды и фактический
результат первого прогона находятся в `BASELINE.md`.
